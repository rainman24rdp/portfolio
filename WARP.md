# WARP.md

This file provides guidance to WARP (warp.dev) when working with code in this repository.

## Development Commands

### Running the Application
This project requires **two servers running simultaneously** for full functionality:

**Frontend (React + Vite):**
```bash
npm run dev
```
- Runs on `http://localhost:5173`
- Hot module reload enabled

**Backend (Express API):**
```bash
npm run server
```
- Runs on `http://localhost:3001`
- Handles photo uploads and serves static files

### Build and Quality
```bash
npm run build      # Build for production
npm run preview    # Preview production build
npm run lint       # Run ESLint
```

## Architecture

### Dual-Server Architecture
This is a **monorepo containing both frontend and backend** in a single package.json. The frontend and backend are separate processes that communicate via HTTP:

- **Frontend**: React 19 SPA with React Router DOM, built with Vite
- **Backend**: Express server with file upload capabilities (Multer)
- **Communication**: Frontend makes fetch requests to `http://localhost:3001/api/*`

### Data Storage
- **Photo metadata**: Stored in `photos-metadata.json` at project root (created by backend on first upload)
- **Photo files**: Stored in `uploads/` directory at project root
- **No database**: Simple file-based storage system

### Frontend Structure
- **Entry**: `src/main.jsx` → `src/App.jsx`
- **Routing**: All routes defined in `App.jsx` using React Router DOM
- **Layout**: `src/components/Layout.jsx` provides consistent navigation and footer
- **Pages**: Each route has a corresponding file in `src/pages/`
  - Home, About, Projects: Static content pages
  - Photography: Fetches and displays photos from API
  - Admin: Photo upload interface with drag-and-drop

### Backend API Endpoints
Defined in `server.js`:
- `POST /api/upload` - Upload photo with title and category (multipart/form-data)
- `GET /api/photos` - Retrieve all photo metadata
- `DELETE /api/photos/:id` - Delete photo by ID
- `GET /uploads/:filename` - Serve uploaded images (static files)

### File Upload System
- Uses Multer with disk storage
- 10MB file size limit
- Accepts: jpeg, jpg, png, gif, webp
- Filenames are timestamped with random suffix for uniqueness
- Original filename preserved in metadata

## Important Patterns

### API Base URL
Frontend components hardcode `http://localhost:3001` for API calls. When modifying API calls, maintain this pattern for local development. For production, these would need to be environment variables.

### Photo Metadata Structure
```javascript
{
  id: timestamp,
  filename: "unique-filename.jpg",
  originalName: "user-filename.jpg",
  title: "User Title",
  category: "Nature|People|Urban|Travel|Architecture|Other",
  url: "/uploads/filename",
  uploadedAt: ISO timestamp
}
```

### Mobile/Cross-Device Upload
The admin interface is designed to work across devices. To upload from mobile:
1. Both servers must be running
2. Access frontend via computer's local IP (e.g., `http://192.168.1.x:5173/admin`)
3. Find IP with: `ifconfig` (Mac/Linux) or `ipconfig` (Windows)

## Key Files
- `server.js` - Express backend, all API routes and upload logic
- `src/App.jsx` - React Router configuration, all routes
- `src/components/Layout.jsx` - Site navigation and layout wrapper
- `src/pages/Admin.jsx` - Photo upload UI with drag-and-drop
- `src/pages/Photography.jsx` - Photo gallery display with API integration
- `photos-metadata.json` - Generated by backend, stores all photo data
- `uploads/` - Directory for uploaded photos (gitignored)
